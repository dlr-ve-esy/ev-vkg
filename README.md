# Public EV charging infrastructure virtual knowledge graph

This repository is the code supporting the publication "Are European electric vehicle charging infrastructure data machine-actionable? A FAIR assessment through virtual knowledge graphs".

## Usage

To work with this repository you need to acquire the data from
 [![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.17422740.svg)](https://doi.org/10.5281/zenodo.17422740). The script `get_data.py` can be used to download it automatically and saved in the right folder.

The archived version of the analysis code is available at [![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23393023.svg)](https://doi.org/10.5281/zenodo.23393023).

This repository depends on work from other contexts, the external repository can be imported by using the terminal to go to this folder after cloning and using git.

```bash
git submodule update --init --recursive
```

Once the data is in the main folder you need to install the dependencies. I recommend using [uv](https://github.com/astral-sh/uv) which will manage these for you. But any python package management should work. Otherwise using your favorite python environment management tool you can activate your env and install:

```bash
pip install -e .
```
To get the archived version of the data you can run the `get_data.py` script.

```bash
python get_data.py
```
Or with uv:

```bash
uv run get_data.py
```

The knowledge graph can be built and explored using the marimo notebook `main.py`, calling:

```bash
uv run marimo edit main.py
```

Or using the pip installation of marimo, calling:

```bash
marimo edit main.py
```

## Regenerating paper figures

Run `uv run marimo edit main.py` and let the notebook finish with your chosen
sources. Its final cell writes the computed figure inputs to
`viz_data/query_results/`. These generated files are ignored by Git. Then run:

```bash
uv run python export_widget_pngs.py --output images
```

The exporter detects Chrome/Chromium/Edge on macOS, Linux, and Windows; use
`--browser /path/to/browser` if needed. D3 is loaded from esm.sh, so rendering
requires internet access. `--scale 3` is the default print resolution.

Individual widgets can be exported without loading unrelated query results:

```bash
uv run python export_widget_pngs.py --only results_plot --output images
uv run python export_widget_pngs.py --only vkg_schematic --output images
```

PNG files are written under `images/`, with manuscript copies under
`images/paper/`: sources = `figure_1.png`, FAIR assessments = `figure_2.png`,
calculated/reference power = `figure_4.png`, merged capacity panels =
`figure_5.png`, and power-band counts = `figure_6.png`. Partial exports only
copy figures generated by that invocation. Export both capacity panels together
to regenerate figure 5. The schematic is exported as `vkg_schematic.png`.

The exporter consumes current calculations; it does not assert agreement with
published numbers or write replacement results. Rerun the notebook after data
or source-selection changes. `--query-dir PATH` can select another completed
run's inputs. The FAIR bars use main's existing per-source assessment scores,
including separate snapshot records; compact labels are generated for display
and the JSON retains each full `source_id`. They are not stable dataset IDs.

This recovery preserves main's scoring, graph construction, source selection,
and error calculations. It does not include the audit branch's revised analysis
methodology, parser changes, fixed result tables, or canonical-result writer.
The static EAFO CSV files are reference observations, not calculated outputs.

Exporter regression checks: `uv run python -m unittest discover -s tests -v`.
